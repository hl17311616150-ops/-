## 1. 意图与背景（Intent & Why）

### 1.1 产品定位
**归野是一个以"对话式 AI 行程规划师"为核心的旅游 App。** 用户用自然语言说出时间和目的地，AI 像聊天一样逐步引导，最终给出一份包含**每日行程、附近景点、每晚住宿**的完整方案；不满意可以一句话让它改。

### 1.2 为什么推翻重来
旧 V2（PRD v0.6）的核心是"在 V1 基础上叠加高德地图/POI"，但存在方向性问题：
- 锁死手机 App 尺寸（390×844）、PWA 打包、真机实测、P0-2 设计系统调试台——这些是工程手段，不是产品价值；
- 保留"出行 deadline/出行条件"等 V1 包袱；
- 没有真正的智能，只是把 POI 堆给用户。

用户明确"全都要重来"：重做 UI、布局、交互，去掉出行条件，新增 AI 助手，不锁死尺寸，不要 PWA/真机实测/调试台。

### 1.3 核心价值主张
- **对话式**：说需求 → 给整份方案 → 一句话改，零学习成本；
- **分步引导**：AI 不一次性甩计划，而是先问时间、再确认路线、再逐点选景点，最后才生成；
- **完整可执行**：真实地图 + 按天编排（含自驾段里程时长）+ 每晚住宿，拿到就能走；
- **社区可复用**：他人的路线可以一键复制，带进 AI 流程改成自己的。

## 2. 目标、非目标、反目标

### 2.1 目标（Goals）
1. 对话式 AI 行程规划：从零规划 + 改进已有路线；
2. 分步引导：时间（含时段）→ 路线确认（校验地理重叠/顺序）→ 逐点选景点 → 生成；
3. 完整行程产出：真实地图总览 + 按天编排 + 每晚住宿；
4. 行程回顾：日记图文混排 + 照片聚合，全屏照片与日记联动；
5. 社区：浏览、讨论、路线复制、发布；
6. 首页品牌沉浸：全屏风景 + 一个主按钮，视觉对齐 Path App。

### 2.2 非目标（Non-goals，本期不做）
- 平板 / 桌面适配（先用 `max-width:480px; margin:0 auto` 留余地，后续适配）；
- 后端 / 账号 / 云同步（继续单用户本地，数据模型按"可上云"设计）；
- 真实支付、实时票务、酒店预订交易（住宿只做推荐，不做下单）；
- 相机功能（V1 本就无真相机，仅图标 + file input）；
- 独立照片墙入口（照片墙并入足迹）。

### 2.3 反目标（Anti-goals，即使技术上能做也不允许）
- 首页拥挤、出现多个并列入口，破坏"一个主按钮"的干净；
- 主按钮随状态移动位置（必须钉在固定位置）；
- 把 POI 原样堆给用户（混入农家乐、采摘园等无关结果）；
- 常驻底部 Tab 破坏首页全屏沉浸；
- 为了"看起来智能"而编造数据、给无法落地的行程。

## 3. 约束（Constraints）

### 3.1 技术栈（沿用基线，不擅自更换）
- React + Vite + TypeScript（strict）+ Tailwind CSS v4 + react-router；
- 质量门：tsc strict / oxlint / 单测 / e2e；
- 本地存储：配置类走 localStorage（`travel:v1:` 命名空间 + schema 版本迁移），照片走 IndexedDB。

### 3.2 设备与布局
- 本期手机优先；布局用 `max-width:480px; margin:0 auto`，不写死 390px；
- 触控目标：可见图标 36px，**点击热区不小于 44×44px**。

### 3.3 本期能力边界（用户已拍板，外部依赖后置）
- **AI 能力：先本地模拟。** 对话理解、行程生成、优化建议用预设脚本/本地规则 + 假数据实现，先把分步流程和界面做扎实；不依赖模型 API key、联网、费用。真实大模型接口后续再接。
- **地图/POI：先用内置数据。** 景点用现有 `data/destinations.ts`（约 28KB 内置库），地图用示意图，先跑通流程；真实高德地图/POI 后续再接（接入时 POI 须经分类快筛、排序、点内搜索，懒加载 + 本地缓存，不能原样堆、避免配额超限）。
- **交通方式：只做自驾。** 行程按自驾段编排、标里程时长；高铁/飞机/公共交通后续。

### 3.4 明确去掉（用户已拒绝）
出行 deadline/出行条件、PWA 打包、真机实测、设计系统调试台、390×844 尺寸锁死、相机功能、独立照片墙入口、按钮随状态移动、卡片栈左右偏移、白底普通社区卡片、功能区底部 Tab。

## 4. 方案取舍（Approaches）

> 以下方案均在对话中呈现并由用户拍板。

### 4.1 整体导航：封面放射式（选）vs 功能区底部 Tab
- **A 封面放射式（选）**：首页无 Tab、全屏沉浸，右上角毛玻璃小图标进社区/我的，主按钮进规划，各页顶部返回首页。
  - 取舍：首页最沉浸、语言统一；社区与我的互切需回首页（多一次点击，但二者切换频率低）。
- B 功能区底部 Tab：首页仍无 Tab，进入社区/我的后出现轻量 Tab。
  - 取舍：互切更快；但功能页多常驻条，与沉浸风格有出入，且规划不进 Tab、逻辑稍绕。
- **选 A 的理由**：首页是品牌门面，值得保持最干净。

### 4.2 导航入口位置：右上角（选）vs 中右侧 vs 左右滑动
- **右上角（选）**：低频入口、零学习成本、不遮挡风景；热区放大到 44px 缓解大屏难够。
- 中右侧悬浮：好点但遮挡风景、像"悬浮客服球"，不高级，且与主按钮区域冲突。
- 左右滑动切页：最沉浸但发现性差，与底部卡片栈横滑、全屏照片联动横滑冲突，且让首页变成"平行页面"，破坏封面定位。
- **选右上角的理由**：社区/我的是低频入口，高频"规划"主按钮在中部已易达，不值得为低频入口牺牲风景。

### 4.3 AI 规划交互：分步引导（选）vs 一上来给计划
- **分步引导（选）**：AI 先问何时出发、几天、何时返程，再逐点列景点供勾选，最后才给规划。
- 一上来给计划：用户还没给信息就出方案，必然不准、返工。
- **选分步的理由**：信息不全时不出方案，每步都让用户确认，结果更准。

### 4.4 行程回顾：日记图文混排（选 A）vs 日记纯文本
- **模式 A（选）**：日记图文混排（照片在日记条目里、有上下文）；"照片"Tab 是该行程所有照片的聚合网格。照片只存一份，两视图不重复。
- 模式 B：日记纯文本，照片全去"照片"Tab。
  - 取舍：结构最简，但回顾时"这段话配的哪张图"对不上，图文割裂。
- **选 A 的理由**：游记的图文本来就是绑定的。

### 4.5 社区视觉：深色杂志沉浸风（选）vs 白底普通列表
- **深色杂志风（选）**：风景 banner + 衬线标题 + 毛玻璃分类，卡片是"风景图 + 文字叠图"的大图卡，深色背景让风景更突出。
- 白底普通列表：信息规整但"太普通、没设计感、跟首页拉太开"。
- **选深色杂志风的理由**：与首页一套沉浸语言。

### 4.6 社区信息效率：双视图切换（选）
- 杂志视图（默认，"逛"）+ 右上角一键切路线视图（"快速复制"）：
  - 路线视图为紧凑列表，一屏 4–6 条，每条含缩略图/标题/天数·里程·难度/经过节点/绿色圆形一键复制按钮，可按热度/天数/里程排序、按难度筛选。
- **选双视图的理由**：兼顾"好看"与"信息快速获取"，社区同时承载路线复制功能。

## 6. 具体设计

### 6.1 首页（三状态）

**结构**：全屏山湖壁纸；左上角小 logo + "归野"；衬线大标题；**每日一句山野诗**；小字功能说明；一个主按钮；底部"今日热门线路"卡片栈。

**每日一句（山野诗）**：
- slogan 下方显示一句完整的旅行/山野诗句，衬线斜体、带引号、标注作者（如"行到水穷处，坐看云起时。——王维"）；
- **按日期取句**：以当天日期为种子，同一天固定同一句，零点后自动换；不是每次刷新随机（避免内容乱跳）；
- 诗句库离线内置（王维、苏轼、李白、陆游等一批），不联网；
- 诗句（衬线、氛围）与功能说明（无衬线、信息）视觉分层；诗句控制在一行，**主按钮位置不动**。

**三状态（按钮位置完全一致，只改文案/轻提示/样式）**：
1. **全新**：毛玻璃"开始规划行程"；
2. **草稿**：轻提示"上次规划到'选景点'，还差一步" + 毛玻璃"继续规划行程"（回中断点）+ 小字"或开始新的规划"；
3. **已生成**：轻提示"你有一份'皖南古村 6 日'" + 白色实心"查看我的行程" + 小字。

**卡片栈（倒梯形）**：三张卡片左边缘对齐、只向下错开（无左右偏移）、上下间距很小；
- c1 最宽（100%），c2 向下 10px 且左右缩进 2%（宽 96%），c3 向下 20px 且缩进 4%（宽 92%）；
- 缩略图依次略小（62→59→56），整体靠近底部，呈倒梯形。

**定稿精确参数**（mockup：`home-final.html`）：
- 壁纸 xUxllTmozI；衬线标题 34px（"归山野，"700 / "见自己"500）；
- 每日诗句 margin-top14，衬线 13px 斜体带引号，作者 11px；功能说明 margin-top12，无衬线 11.5px；
- 主按钮全新态 margin-top:44，毛玻璃（rgba(255,255,255,.18)+border rgba(255,255,255,.5)+blur12）；
- 草稿/已生成态：hint margin-top16，按钮 margin-top12，小字 margin-top11；
- 右上角两个毛玻璃图标（社区=指南针、我的=人像），可见 36px、热区 44px。

### 6.2 AI 规划流程

#### 6.2.1 分步引导
顶部步骤条：时间 → 路线 → 选景点 → 生成。AI 用对话气泡引导，关键信息用卡片确认，底部始终可输入补充。

#### 6.2.2 时间卡（步骤 1）
- 出发、返程各含：**日期 + 上午/下午/晚上三档时段**；
- 以"出发（日期+时段）+ 返程（日期+时段）"为基准，自动算出：
  - **X 天 X 晚**、**X 个完整游玩日**、首尾半天；
- 总天数可手动改（步进器），**联动顺延返程日期与晚数，不允许三字段打架**；
- 自然语言解析为主（如"8号上午走、13号晚上回"），卡片只做确认；
- 粒度锁三档，不做具体钟点。
- 示例：8 号上午出发、13 号晚上返程 = **6 天 5 晚、4 个完整游玩日（9–12 号）**，首日下午起、末日玩至傍晚。

**时段的作用**：修正首尾两天的游玩时长和住宿晚数（首日上午出发则当天可玩半天，晚上返程则当天可玩到傍晚）。

#### 6.2.3 路线确认（步骤 2）
AI 校验三类，用户拍板：
- **地理重叠（已采纳）**：如"宏村在黟县境内，西递也在黟县"——**采纳：把宏村作为黟县的重点村安排，不另算城市**，想去的点都保留；
- **顺序顺路**：当前点顺序有无明显绕路（仅告知）；
- **时间合理**：天数与最长自驾段是否匹配（仅告知）。
- 底部："按我原样来" / "确认，去选景点"。

#### 6.2.4 逐点选景点（步骤 3，两级结构）
- **点列表**：每点显示已选摘要（"已选 N · 景点名…"），点进去精修；
- **点详情**：
  - 顶部**点内搜索框**；
  - **分类快筛 chips**：全部/自然风景/古村古镇/博物馆/宗教文化；
  - **排序**：热度/距离/评分；
  - 完整 POI 列表（评分、距离、分类、简介），**懒加载**（如"已显示 6/38，滚动加载"）；
  - 底部已选汇总 + 确认；
- 点详情保留已选状态，返回不丢；
- 快捷项：**"全部点帮我定"**（不逐个进去）；
- **不点也能直接生成**（AI 默认勾经典项）。

**关键**：高德 POI 不能原样堆（混入农家乐/采摘园），必须经分类、排序、搜索处理；数据懒加载 + 本地缓存避免配额超限。

#### 6.2.5 生成结果（步骤 4）
- **真实地图总览**（高德）：各点连线、可缩放、点节点看详情；
- **摘要条**：6天5晚 / 自驾 / 5城 / 14景点；
- **按天卡片**：
  - 上午/下午/晚上时段编排；
  - 自驾段标里程时长（如"自驾 500km · 约 5.5h"）；
  - 每晚住宿（酒店/民宿，含早、可停车等），带"换"入口；
- 底部："AI 再调整" / "保存行程"。

#### 6.2.6 改进已有路线 · AI 优化建议
三类建议，每条带理由，可逐条"采纳/忽略"，底部"全部采纳并重新生成"：
- **节奏**：如"Day2 长沙→景德镇 500km，当天还排橘子洲偏赶，建议橘子洲移到 Day1 上午"；
- **顺路**：如"西递、宏村相距仅 11km，建议两晚连住黟县片区，少搬一次行李"；
- **补住宿**：如"Day4 西递当晚还没选住宿，推荐西递·耕乐堂民宿（评分 4.7、景区内、可停车）"。

### 6.3 行程回顾

#### 6.3.1 日记 / 照片 Tab（模式 A）
- **日记 Tab**：图文混排，每条日记含时间、地点、照片（缩略）、文字；
- **照片 Tab**：该行程所有照片的聚合网格，快速翻图；
- 照片只存一份（IndexedDB），两个 Tab 只是不同查看方式，不重复存储；
- 纯文字日记不进全屏照片流。

#### 6.3.2 全屏照片 · 日记联动
- 日记 Tab 或照片 Tab 点照片 → 全屏；
- 底部日记文字随照片走：**照片按张翻，文字按"所属日记条目"切换**；
  - 同一条日记的多张照片共用文字，翻到下一条日记才更新；
- 文字叠底部 + 渐变遮罩，长文限行可展开；
- 顶部关闭 + 计数（2/38），左右有滑动提示，底部页面点。

### 6.4 社区

#### 6.4.1 信息流（双视图）
- **杂志视图（默认）**：
  - 顶部风景 banner（深色渐变）+ 衬线"发现山野" + 毛玻璃分类 chips；
  - 编辑精选全宽大卡 + 热门路线两列小卡 + 全宽卡；
  - 卡片为"风景图 + 文字叠图"，深色背景；
- **路线视图（一键切换）**：
  - 紧凑列表，一屏 4–6 条；
  - 每条含缩略图、标题、天数·里程·难度、经过节点、绿色圆形一键复制按钮；
  - 可按热度/天数/里程排序，按难度筛选。

#### 6.4.2 游记详情（深色沉浸）
- 风景封面（返回/收藏/分享毛玻璃圆）；
- 作者 + 关注；衬线标题 + 元信息（日期、天数晚数、里程、难度）；
- 路线节点卡；
- 日记/照片 Tab，点照片进全屏联动；
- 点赞/评论/收藏条；
- 底部白色"用这条路线规划"（带进 AI 分步引导）。

#### 6.4.3 发布流程
- **行程结束"整理并发布"**：
  - 选封面（可更换）、改标题、勾选要公开的日记（可取消不想公开的）、选可见范围（公开/好友/仅自己）；
- **途中单条"边走边发"**：
  - 日记里把某条立刻发到社区，形成"进行中"的实时游记（ongoing），回来点"整理并发布"收尾固化（completed）。

## 7. 数据与存储

### 7.1 现状（已读取基线）
- `storage/schema.ts`：`SCHEMA_VERSION=1`，`registerMigration(from, fn)` + `runMigrations()` 逐级迁移机制；
- 数据模型 `types.ts`：`Trip`（含 departDate、totalDays、waypoints、diary、departed 等）、`DiaryEntry`（photoIds 引用）、`PhotoEntry`；
- 照片有**新旧两套路径并存**：
  - **新**：`lib/album.ts` 走 IndexedDB（DB `guiye` / STORE `album`），照片压缩（长边 1280、JPEG 0.7），`AlbumPhoto`；
  - **旧**：`lib/footprint.ts` 的 `getPhotos/addPhoto` 走 localStorage（`K.photos`，`PhotoEntry`）。

### 7.2 本期数据工作
1. **统一照片路径**：照片统一走 IndexedDB（album），废弃 `footprint.getPhotos/addPhoto` 的 localStorage 路径；
2. **一次性迁移**：启动时调用 `album.migrateLegacyPhotos()`（已实现）把 `travel:v1:photos` 旧照片迁入 IndexedDB，迁完清旧 key；
3. **数据模型扩展**（走 schema 迁移，bump 到 v2）：
  - Trip 增加：返程日期、出发/返程时段、按天行程（day plans）、每晚住宿、AI 生成状态/草稿断点；
  - 社区帖子已有结构化 `nodes`（供复用导入），沿用；
  - 新增字段一律经 `registerMigration` 迁移，不静默改 shape。

### 7.3 数据安全
- 照片删除条目时只删引用、保留相册库照片（沿用现有逻辑）；
- 回收站软删除、30 天惰性清理、可恢复/彻底删（沿用）。
