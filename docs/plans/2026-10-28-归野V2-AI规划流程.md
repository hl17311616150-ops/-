# 归野 V2 · AI 规划流程（Plan 2）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 Plan 1 地基上实现对话式 AI 规划的前三步——时间（日期+时段）→ 路线输入与确认（地理重叠/顺序/时间校验）→ 逐点选景点（点列表/点详情），完成后草稿推进到 `result`，生成结果由 Plan 3 实现。

**Architecture:** PlanFlow 是一个独立全屏流程，持有单份 `PlanningDraft`（已在 Plan 1 落地持久化），按 `draft.step` 渲染对应步骤；AI 用对话气泡引导、关键信息用卡片确认，底部常驻输入框。所有"理解/校验/查询"为纯函数（本地模拟，不联网、不接模型/高德），UI 组件只负责渲染与调用。

**Tech Stack:** React 19 + TypeScript 6（strict）+ Tailwind v4 + react-router-dom 7 + vitest；复用 `lib/time`、`planningDraft`、`storage`。

**Spec:** `docs/specs/2026-10-28-归野V2-design.md`（§6.2 AI 规划流程）。

## Global Constraints

- 不新增运行时依赖；不引入状态管理库（用 React useState/useReducer）。
- AI 全部本地模拟：时间/路线/图片理解、路线校验、POI 均为内置规则与假数据，不联网、不接模型 key、不接高德。
- 类型严格：`tsc -b` 零错误；读取草稿/旧数据一律容错（缺字段兜底），不白屏。
- 布局：`max-width:480px; margin:0 auto`；触控目标可见 36px、热区 ≥44px。
- 存储：草稿经 `planningDraft.ts` 的 `getDraft/saveDraft/createDraft/clearDraft`；不直接散落 localStorage。
- 文案：AI 引导用简洁口语；时间粒度锁三档（上午/下午/晚上），不做具体钟点。
- 质量门：`npm run test` / `npm run lint` / `npm run build` 全绿。
- Git：可执行 `D:\软件\Git\cmd\git.exe`；提交用 `feat:` 前缀。

## Review Focus

1. **时间自然语言的多种说法**：缺月份的"8号走、13号回"、"X月Y日"、时段只写一个时，`parseTimeText` 必须正确补默认时段（出发默认上午、返程默认晚上），凑不齐两个日期返回 null（不抛错）。→ 测试加在 Task 2。
2. **路线分隔符**：`- — → 到 ， , 空格 换行` 及混合分隔，`parseRouteText` 都要正确拆分、去空去重。→ 测试加在 Task 4。
3. **手动改天数联动返程**：在时间卡把总天数 ±1 时，返程日期必须顺延/回退、晚数同步，不能出现"天数变了返程日期没变"。→ 测试加在 Task 3。
4. **搜索+分类+排序同时生效**：点详情里输入搜索词、选分类、改排序三者叠加时，结果集是三者的交集且按所选排序，不互相覆盖。→ 测试加在 Task 7。
5. **地理重叠多个子点**：西递、塔川、宏村都在黟县，`checkRoute` 要为每个同时出现的父子对生成"需决定"，不遗漏。→ 测试加在 Task 5。

### Task 2: 时间自然语言解析纯函数

**Files:**

**Interfaces:**
- Produces:
  - `interface ParsedTime { depart: TimeAnchor; back: TimeAnchor }`
  - `parseTimeText(text: string, refYear: number, refMonth: number): ParsedTime | null`
  - 规则：日期 `X月Y号|日` 或 `Y号|日`（缺月用 refMonth）；时段词 morning=上午/早上/早晨/早/清晨，afternoon=下午/中午/午，evening=晚上/晚/傍晚/黄昏/夜里；动作 出发=走/出发/动身，返程=回/返程/回来/到家；出发动作的日期为 depart、返程动作为 back；无动作词时两个日期的先后为 depart/back；时段缺省 depart=morning、back=evening；凑不齐两个日期返回 null。

### Task 5: 路线校验逻辑（地理重叠 / 顺序 / 时间）

**Files:**
- Modify: `src/types.ts`（PlanningDraft 加 `pointGrouping?: Record<string, string>`）、`src/lib/planningDraft.ts`（createDraft 初始化 `pointGrouping: {}`）
- Create: `src/lib/plan/routeCheck.ts`
- Test: `src/lib/plan/routeCheck.test.ts`、同步 `planningDraft.test.ts`

**Interfaces:**
- Consumes: `TripTimeSummary`（`lib/time`）。
- Produces:
  - `type CheckKind = 'overlap' | 'order' | 'time'`
  - `interface RouteCheck { kind: CheckKind; level: 'decide' | 'info'; title: string; detail: string; child?: string; parent?: string }`
  - `checkRoute(points: string[], time?: TripTimeSummary | null): RouteCheck[]`（time 缺失时只生成 overlap/order，不生成 time 检查）
  - 内置归属表 `POINT_PARENTS: Record<string,string>`：`{ 宏村:'黟县', 西递:'黟县', 塔川:'黟县', 卢村:'黟县', 木坑:'黟县', 南屏:'黟县' }`；points 同时含 parent 与 child 时，每对生成一条 `overlap/decide`（title“宏村在黟县境内”，detail 建议作为重点村、不另算城市）。
  - 顺序：内置简化顺序表，当前顺序与表一致 → info“当前点顺序无明显绕路”，否则 info 提示可能绕路（仅告知）。
  - 时间：内置简化里程表（如 长沙→景德镇 500km），若存在单日明显超长（>500km/天）则 info 提示偏赶，否则 info“时间合理”。
