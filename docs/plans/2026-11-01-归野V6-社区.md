# 归野 V6 · 社区（信息流双视图 + 深色游记详情）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把社区占位页做成深色杂志风信息流（杂志/路线双视图）+ 深色沉浸游记详情，并消除首页热门卡片 → 社区详情的 id 命名空间 404。

**Architecture:** 新建独立社区离线数据（6 条帖子，id 与 `HOT_ROUTES` 完全一致），帖子含作者、路线节点、游记条目（复用 `DiaryEntry` 结构）；社区照片以独立前缀 `comm_<postId>_<n>` 幂等播种进 IndexedDB。杂志视图与路线视图是同一份数据的两种渲染；详情页复用已封板的 `PhotoGridTab`（透明背景）与 `FullscreenViewer`（中性深色），社区专属深色组件独立新建，不改动已封板的浅色行程组件。

**Tech Stack:** React 19、Vite 8、TS 6 strict、Tailwind v4、react-router-dom 7、vitest 5（jsdom + fake-indexeddb）、oxlint。

**Spec:** `docs/specs/2026-10-28-归野V2-design.md` §6.4 社区（240–270 行）、§5 IA（121–141 行）、§8 开发者清单（306–318 行）。

- 不新增依赖；只读 + 本地模拟，不接真实后端/大模型/联网。
- 页面最大宽 480px，整体深色背景 `#1c2621`；衬线栈 `"Noto Serif SC","Songti SC",serif`。
- 关键视觉值用 inline style 便于 jsdom 断言（jsdom 无布局），结构性布局用 Tailwind；视觉精确值逐字来自 mockup。

## Review Focus

1. **未知/非法帖子 id**：直接访问 `/community/不存在的id` 或首页卡片 id 与帖子数据错位时，应显示兜底提示与返回入口，不白屏、不抛未捕获异常 —— Task 5 测试。
2. **IndexedDB 播种失败**：社区照片播种 reject 时，列表/详情应进入错误态并可重试，不永久停在 loading —— Task 4 测试。
3. **纯文字游记条目**：photoIds 为空的条目不进入全屏照片流，但其文字在日记 Tab 正常显示 —— Task 6 测试。
4. **双视图数据一致**：杂志视图与路线视图渲染同一份帖子数据，排序/筛选只影响路线视图，切换视图不丢数据、不重复播种 —— Task 4 测试。
5. **互动计数边界**：点赞/收藏在本地态切换时计数 ±1 且可反复切换回原值，不出现负数或重复累加 —— Task 6 测试。
