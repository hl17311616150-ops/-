# 归野 V2 · AI 生成结果（Plan 3）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 Plan 2 完整草稿（时间/路线/分组/已选 POI）基础上，生成并展示完整行程——地图总览、摘要条、按天卡片（时段编排/自驾段/每晚住宿），并提供 AI 优化建议（节奏/顺路/补住宿，逐条或全部采纳）与保存行程。

**Architecture:** 生成、建议、转换均为纯函数（本地模拟，不联网、不接模型/高德）；结果步骤 ResultStep 持有生成的 DayPlan[]，用 PlanMap / DayCard / SuggestionList 渲染。住宿为新增本地数据层；自驾里程复用 routeCheck 的里程表（导出查询函数）。

**Tech Stack:** React 19 + TypeScript（strict）+ Tailwind v4 + react-router-dom 7 + vitest；复用 `lib/time`、`lib/plan/{pois,routeCheck}`、`storage`、`types`。

**Spec:** `docs/specs/2026-10-28-归野V2-design.md`（§6.2.5 生成结果、§6.2.6 优化建议）。

## Global Constraints

- 不新增运行时依赖；不引入状态管理库（用 React useState/useMemo）。
- AI 全部本地模拟：行程生成、优化建议、住宿/POI/里程均为内置规则与假数据，不联网、不接模型 key、不接高德。
- 类型严格：`tsc -b` 零错误；读取草稿/旧数据一律容错（缺字段、坏 id 兜底），不白屏。
- 布局：`max-width:480px; margin:0 auto`；触控目标可见 36px、热区 ≥44px。
- 存储：草稿经 `planningDraft.ts`；生成行程保存经 `storage/store` 的 `K.trip`，不散落 localStorage。
- 文案：AI 用简洁口语；时段锁三档（上午/下午/晚上）；地图/自驾标注"本地示意，真实数据待接入"。
- 质量门：`npm run test` / `npm run lint` / `npm run build` 全绿。
- Git：可执行 `D:\软件\Git\cmd\git.exe`；提交用 `feat:` 前缀。

## Review Focus

1. **城市合并（分组子点）**：宏村分组到黟县时，城市序列必须去重为 4 城、且宏村的 POI 仍计入黟县，不能丢景点或重复算城市。→ 测试加在 Task 2。
2. **天数与住宿一致**：N 天必须有 N-1 晚住宿、住宿落在当天所在城市，不能出现"天数对、住宿晚数错"或"住到下一个城市"。→ 测试加在 Task 2。
3. **自驾段里程**：城市切换必须生成 DriveSegment；里程表查得到标里程时长、查不到只写"自驾前往"，不能缺段或报错。→ 测试加在 Task 2。
4. **首日/末日边界**：出发日含出发块、返程日含返程块，且不超出总天数；depart/back 时段正确占用。→ 测试加在 Task 2。
5. **优化建议采纳后真的改行程**：采纳补住宿要填上、采纳连住要统一、采纳节奏要移动 POI，不能只改状态不改 dayPlans。→ 测试加在 Task 3。

### Task 2: 行程生成器 buildPlan（核心纯函数）

**Files:**
- Modify: `src/types.ts`（Stay 扩展 optional 字段）
- Modify: `src/lib/plan/routeCheck.ts`（导出 `mileageBetween`）
- Create: `src/lib/plan/buildPlan.ts`
- Test: `src/lib/plan/buildPlan.test.ts`

**Interfaces:**
- Consumes: `PlanningDraft/DayPlan/ScheduledBlock/DriveSegment/Stay`（types）、`computeTripTime`（lib/time）、`queryPois`（plan/pois）、`defaultStay/queryStays`（Task 1）、`mileageBetween`（routeCheck）。
- Produces:
  - `buildPlan(draft: PlanningDraft): DayPlan[]`
  - `resolveCities(draft): { city: string; subPoints: string[] }[]`（导出，便于测试）
  - `allocateDays(cities: { city: string; subPoints: string[] }[], totalDays: number, draft: PlanningDraft): number[]`（导出）
  - types.ts 的 `Stay` 扩展：`stayId?: string; rating?: number; tags?: string[]`（均 optional，旧数据不受影响）。
  - routeCheck 新增导出：`mileageBetween(a: string, b: string): number | null`（把现有私有函数改为 export，逻辑不变）。

  规则：
  0. **总天数**：`draft.depart` 与 `draft.back` 均非空时 `totalDays = computeTripTime(depart, back).totalDays`；否则兜底 `totalDays = max(1, points.length)`（理论上 result 步必有锚点，容错不白屏）。
  1. **城市合并**：按 points 顺序遍历；`pointGrouping[child]=parent` 的子点合并到已出现的 parent 的 subPoints（不新建城市）；未分组点各为一城市；保持顺序。
  2. **POI 收集**：城市的 POI = 其所有 subPoints 的 `selectedPois[subPoint]` 展开，按 subPoint 顺序、数据顺序去重（id）。
  3. **最少天数**：城市第一天容量 = 2 个时段（出发城市被出发块占 1、自驾到达城市被自驾段占 1）；后续完整日容量 3。POI 数 p：p≤2 → 1 天；否则 `1 + ceil((p-2)/3)` 天。
  4. **分配**：先给每城市最少天数；剩余 R = totalDays − 最少总和，贪心 R 次：每次给 `POI数/当前天数` 最大（并列取靠前）的城市 +1；R<0 时按最少天数（不裁剪 POI）。
  5. **编排**（按城市顺序）：每天 `date = addDays(draft.depart.date, dayIndex)`（无锚点时用 `day-{dayIndex+1}` 占位）。
     - 第一城市第一天：depart.period 时段放出发块（title“出发，前往 {city}”，note“首日行程不排满”）；其余时段顺序填 POI。
     - 非第一城市第一天：第一个时段（morning）放自驾段：`mileageBetween(prevCity, city)`，查到则 `distanceKm=km`、`durationMin=round(km/90*60)`；查不到则两者 0。ScheduledBlock `{ period:'morning', title:'自驾前往 {city}', drive:{from:prevCity,to:city,distanceKm,durationMin} }`；其余时段填 POI。
     - 城市后续完整日：morning/afternoon/evening 顺序填 POI。
     - 最后城市的最后一天：back.period 时段放返程块（title“返程”，note“返程回到家”）；之前时段填 POI。
     - POI 块：`{ period, title: poi.name, poiId: poi.id, note: poi.desc }`。
  6. **住宿**：每天（除最后一天）末尾写 stay：`defaultStay(当天城市)`，构造 `{ nightIndex: dayIndex, name, location: city, changed:false, stayId, rating, tags }`；defaultStay 为 undefined 时该晚 stay 缺省（不报错，交建议补）。

### Task 3: 优化建议生成器与采纳（纯函数）

**Files:**
- Create: `src/lib/plan/suggest.ts`
- Test: `src/lib/plan/suggest.test.ts`

**Interfaces:**
- Consumes: `DayPlan/Suggestion?`、`buildPlan`（Task 2）、`defaultStay/queryStays`（Task 1）、`POINT_PARENTS`（routeCheck）。
- Produces:
  - `type SuggestionKind = 'pace' | 'route' | 'stay'`
  - `interface Suggestion { id: string; kind: SuggestionKind; text: string; why: string; status: 'open'|'accepted'|'ignored'; targetDayIndex?: number; stayId?: string }`
  - `suggest(dayPlans: DayPlan[], draft: PlanningDraft): Suggestion[]`
  - `applySuggestions(dayPlans: DayPlan[], suggestions: Suggestion[], draft: PlanningDraft): DayPlan[]`
  - 规则：
    - **节奏**：某天含 drive（distanceKm≥500）且当天非 drive 的 POI 块 ≥2 → “Day{n} {from}→{to} 车程长，当天还排了多个景点偏赶，建议把靠后的景点移到相邻天。”
    - **顺路**：某城市 subPoints 含 ≥2 个点名（即至少合并 1 个被分组子点，如黟县含 [黟县,宏村]）→ “{子点} 都在 {city} 片区、相距很近，建议连住一处、白天往返，少搬行李。”
    - **补住宿**：(a) 某晚（day 0..n-2）缺 stay → 推荐该城市 defaultStay（每晚一条，targetDayIndex=该晚）；(b) 每个城市至多一条：仅当该城市第一晚 stay 存在（缺 stay 已由 (a) 处理，不访问 undefined.tags）、queryStays 含“景区内”、且 stay.tags 不含“景区内” → 推荐该城市第一个“景区内”住宿：“{city} 当晚推荐 {name}（评分 {rating}、景区内、可停车）。”
  - 生成时填充：stay 建议 targetDayIndex=该城市第一晚 index、stayId=推荐住宿 id；pace 建议 targetDayIndex=自驾日 index。
  - `applySuggestions`：仅处理 accepted：
    - stay：targetDayIndex 那晚，用 stayId 从 queryStays 取 stay 更新（changed:true）；缺则补上。
    - route：把该城市相邻天的 stay 统一为第一个（连住）。
    - pace：targetDayIndex 自驾日当天最后一个 POI 块移到下一天（无下一天则前一天），保持 period 顺序。

  const out = applySuggestions(days, s, draft)
  const after = out[driveDay].blocks.filter((b) => !b.drive).length
